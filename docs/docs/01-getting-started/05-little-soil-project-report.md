# 小土壤（Little Soil）项目报告

> 版本：0.1（产品验证阶段）  
> 更新日期：2026-09-21  
> 项目性质：以开源 Karakeep 为基础进行二次开发的个人灵感收藏与再发现产品

## 1. 项目摘要

小土壤是一款面向设计师、创作者、研究者和知识工作者的私人素材收藏平台。它解决的不是“再收藏一个链接”，而是“让已经收藏的内容重新变得可理解、可检索、可使用”。

产品以“土壤与养分”为隐喻：来自网页、视频平台和代码社区的收藏如同沉积在土壤中的微量元素；用户通过标签、主题、备注、搜索和 AI 整理，主动吸收这些信息，形成持续生长的个人灵感库。

当前版本已经具备本地可运行、多用户隔离、导入、标签整理、AI 辅助分类、搜索、归档、RSS、备份和基础 AI 点数账本能力。项目尚处于验证与完善阶段，尚不应在没有补齐支付、安全、监控和灾备措施的情况下作为正式商业 SaaS 对外收费上线。

## 2. 产品定位与目标用户

### 产品定位

- 私人灵感素材库，而非公共内容社区。
- 收藏后的整理、再发现与复用工具，而非单纯的稍后读服务。
- 以“标签优先”为核心的信息组织工具：标题和摘要辅助理解，标签承担主要的识别与聚合角色。
- 支持 AI 辅助但保留用户最终控制权的个人知识整理产品。

### 目标用户

- 视觉设计、产品设计、交互设计与品牌设计从业者。
- 前端开发者、独立开发者与技术研究者。
- 有跨平台收藏习惯的创作者、学生与知识工作者。
- 希望将收藏夹从“堆积”转化为“可再利用素材库”的个人用户。

### 核心价值主张

1. **集中**：把分散来源的链接、笔记和资源导入一个私有空间。
2. **理解**：通过标题、原始描述、来源和标签快速识别内容。
3. **整理**：AI 提议标签，用户可确认、替换、补充和批量处理。
4. **再发现**：搜索、主题、重点标记、每日标签推荐帮助旧收藏再次被使用。
5. **可控**：数据默认私有；AI 调用、点数消费与导入均应可追踪。

## 3. 品牌与交互设计

产品中文名为 **小土壤**，英文工作名为 **Little Soil**。视觉系统采用低饱和土壤绿、纸感米白和少量琥珀色，配合刺猬与幼苗的手绘形象：刺猬代表谨慎收集与探索，幼苗代表吸收养分后的成长。

当前界面实践包括：

- 无字刺猬幼苗标志用于应用顶部与站点图标。
- 登录与注册页以“小土壤”作为中文品牌锁定版。
- 主要导入/导出入口在侧栏显著展示。
- 标签在收藏卡片中优先于摘要呈现。
- 每日标签推荐使用简约纯色卡片，避免装饰背景干扰信息。
- 侧栏底部设置可点击的透明底刺猬小宠物，作为轻量反馈，不承担关键功能。
- 支持中文、English 以及架构已有的多语言显示；语言名称应使用各语言自己的书写方式。

## 5. 技术架构

### 技术栈

| 层级       | 采用技术                                 | 职责                                           |
| ---------- | ---------------------------------------- | ---------------------------------------------- |
| Web 前端   | Next.js、React、TypeScript、Tailwind CSS | 应用界面、服务端渲染、路由、多语言与组件交互。 |
| 应用接口   | tRPC、Zod                                | 类型安全的前后端调用、输入校验与权限边界。     |
| 数据访问   | Drizzle ORM、SQLite                      | 本地开发与轻量部署的数据存储、迁移与关系管理。 |
| 搜索       | Meilisearch                              | 收藏内容、标题、标签等的全文检索与检索性能。   |
| 后台任务   | Workers、Liteque 队列                    | 导入、内容抓取、AI 整理、RSS 轮询等异步任务。  |
| 网页处理   | 独立 Chrome 服务                         | 在允许范围内处理网页内容与提取元数据。         |
| 部署运行   | Docker Compose                           | Web、Worker、搜索、Chrome 与数据卷的本地编排。 |
| 测试与质量 | Vitest、TypeScript typecheck、格式化工具 | 关键业务单元测试、编译类型检查与代码风格控制。 |

### 逻辑数据流

```text
用户导入或新增收藏
        ↓
输入校验、去重、创建导入任务
        ↓
后台 Worker 抓取允许访问的元数据并写入数据库
        ↓
搜索索引更新 / 可选 AI 标签任务
        ↓
用户确认标签、补充备注、归入主题或归档
        ↓
搜索、每日推荐和主题页驱动再次发现
```

### 数据与权限原则

- 收藏、标签、主题、备份和点数账本都以用户 ID 为边界查询。
- 所有标签更新先校验标签归属，避免跨用户读取或修改。
- AI 模型密钥只能保留在服务端环境变量中，终端用户不需要自行填写 API Key。
- 收藏内容属于不可信外部数据，不能作为系统指令执行。

## 6. AI 点数设计现状

### 已实现

- 新账户初始发放 100 AI 点数，并保留首次免费体验额度。
- AI 调用通过预留、结算和幂等键降低重复扣费风险。
- AI 执行失败时自动释放或退回已预留点数。
- 管理员可人工发放、扣减点数及附加免费额度。
- 用户可在统计/账本位置查看余额与消费记录基础信息。

### 未实现，禁止宣称已具备

- 真实人民币充值套餐与支付收银台。
- 支付服务端回调验签。
- 订单幂等入账、退款、拒付和异常订单处理。
- 管理员订单检索、人工补单工作流与完整用户账单中心。

在这些能力完成前，AI 点数只能作为体验、运营发放或内部测试额度，不能作为正式付费余额运营。

## 7. 安全、隐私与合规状态

### 已具备的基础原则

- 默认私有收藏；不以公开社区为主要产品模型。
- 不要求用户提供第三方平台密码或浏览器 Cookie。
- 不绕过登录、验证码、付费墙或来源平台访问限制。
- 不下载或托管完整视频，收藏卡片以跳转原来源为主。
- 后端保存 AI 服务凭据，用户侧不暴露平台密钥。

### 上线前必须补齐

1. 邮箱验证、密码找回、异常登录保护、会话策略与安全通知。
2. 正式隐私政策、使用条款、退款规则和可联系的运营主体信息。
3. HTTPS、密钥轮换、限流、反滥用、审计日志和依赖安全扫描。
4. 对象存储：私有桶、服务端加密、短期下载链接与访问控制。
5. 异地备份、恢复演练、恢复时间目标（RTO）与恢复点目标（RPO）。
6. 错误监控、性能监控、任务积压监控、模型成本与支付异常告警。
7. 对来源网站的抓取频率、robots、服务条款与数据处理边界评估。

## 9. 发布评估

### 当前结论

小土壤适合以“本地开发、内部测试、受邀体验”的方式进行产品验证；不建议当前直接作为带真实充值的公开商业服务上线。

### 可进行的下一步

1. 先用真实用户完成导入—整理—找回—再使用的体验验证。
2. 收集标签备注、每日推荐、AI 标签准确度和导入成功率反馈。
3. 确认名称、视觉系统、隐私政策和运营主体。
4. 补齐安全、对象存储、备份演练和监控后，再考虑公开域名与持续服务。
5. 最后接入支付，且仅在服务端回调验签成功后增加点数余额。
